# 设计导航

## 阅读顺序

1. [采购场景与总体设计](采购场景与总体设计.md). 从一笔 800 元模拟订单认识三域角色, 区分身份证据链与采购委托链.
2. [跨域身份与信任](跨域身份与信任.md). 从共同根 T 的域认证及 IA/IB/IC 的本域签发, 判断各方可以相信哪些身份属性.
3. [委托授权与策略](委托授权与策略.md). 确定谁有权签根, G0 到 G2 怎样收缩权限, 以及哪些变化会使路径失效.
4. [请求认证与状态一致性](请求认证与状态一致性.md). 跟随一次挑战, 在选定区块验证路径, 在锁后确定订单能否放行.
5. [威胁模型与安全目标](威胁模型与安全目标.md). 对照攻击者能力, 检查 SG1-SG6 分别依赖哪些前提.

## 维护约定

总体设计维护贯穿各篇的采购示例. 身份根唯一为 T, 两种根授权指采购 G0 权源, 各处须明确区分. T 只认证域及身份签发资格, 各域机构只证明本域主体身份. 身份篇定义属性信任, 委托篇定义权限边界, 请求认证篇定义一次决定所用的证据和时点. 安全目标篇汇总成立前提及其保证. 字段编码和网关操作写入实现规格, 测量参数与判据写入实验计划. 机制变更时, 沿上表同步更新实现契约和验收条件. 涉及部署与容错前提时核对[技术栈](../implementation/技术栈.md).
