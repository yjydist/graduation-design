# 验证用例

本页是[实验 E1/E2](实验计划.md#3-e1-e3-功能-安全与动态轨迹)的执行清单. 每个负例配一条只改该条件的正例, 记录调用者, 实际选块, 首个失败阶段, 挑战是否消费和订单行数.

## 1 采购闭环

| 编号 | 输入或操作 | 验收条件 |
| --- | --- | --- |
| F01 | 安全分发 T 根并部署 AuthRegistry, T 核实三域及 IA/IB/IC, 域内登记 PA, U/A₁/B₁与 C 服务 | 核对 RootRecord/清单一致, PENDING 域不能开展身份业务; 当前域认证确认后可用, PA 业务资格独立于身份签发资格 |
| F02 | 独立夹具另登记 U-in-B, 验证域内账户及应用密钥 PoP, 为 U 与 U-in-B 建立关联提案并双域审批 | 单方确认仍待审批, 两方确认后 effectiveActive; 原账号/盐不公开, 关联不自动授权 |
| F03 | IA/IB/IC 分别为本域主体签发身份凭证, 含 PA 和 C 服务, 登记摘要并等待确认 | PENDING 凭证不能使用, 确认后可解析, 每份身份凭证均可追溯到 T 的对应域认证 |
| F04 | A/B/C 共同信任 T, 验 T 对各域和 IA/IB/IC 的认证, 再验各域主体身份 | IB 证明 B₁属于 B, T 只认证 B 域及 IB 的资格. A/B 能验证 C 的 IC 身份路径, 身份认证不自动授予采购权 |
| F05 | 分别创建两模式任务, C 或 PA 签 G0, U 签 G1, A₁签 G2 | 500000→500000→100000, 深度 2→1→0 |
| F06 | 两模式 B₁完整挑战和证明后询价, 提交 800 元订单 | 两步均允许, 共四次往返, 一份报价和一笔订单, 无业务链上写 |
| F07 | 同路径提交 1200 元订单 | 拒绝且无新订单 |
| F08 | 正常订单响应丢失, 换新挑战, 相同幂等键重试 | 返回同一订单, 不新增业务效果 |
| F09 | 查看 T 根, 各域认证, DID, 身份路径, 两种采购根来源及决策解释 | 与签名对象, 模式, 采购主体和状态版本一致 |
| F10 | BUYER_MANDATE 无任何 C 签的 G0, 仍提交合法 PA 根及同一采购请求 | C 策略接受时允许, 证明没有偷偷复用预授权模式 |
| F11 | 同一合法 PA 根, C 策略拒绝该企业或商品 | SUPPLIER_POLICY_DENIED 且无订单, A 的委托不能强迫 C 成交 |
| F12 | 用未锚定 DID 文档/错误用途密钥访问, 再换成匹配文档 | 非法拒绝/合法通过配对, 不只验证 DID 字符串前缀 |
| F13 | 请求/任务使用不同授权模式, 或伪造 PA 根替代 C 预授权根 | 模式/根权源拒绝, 不能失败后自动切换模式 |
| F14 | 完成根 DID 文档预置和域认证交付后停 T 服务及其 DID 主机, 保持链和各域运行, 执行合法采购 | 无请求时调用 T, 当前资格有效且状态新鲜时仍成功; 域认证到期后拒绝 |
| F15 | T 原子续发同一机构/密钥/范围的域认证, 再轮换 IB 密钥并重新认证 | 前者更新认证材料即可验原有效凭证/委托, 后者须重签引用旧版本的凭证/授权 |
| F16 | 用真实 T/IA/IB/IC 密钥生成域认证及完整证据包, 两端复算 trustPaths/evidenceHash | 记录原始 JWS 和中间字节, 正确向量一致, 篡改认证字节或顺序时原 KB 拒绝 |

## 2 身份, 请求与父子约束

| 编号 | 输入或操作 | 验收条件 |
| --- | --- | --- |
| S01 | 未获 T 认证, 不在当前域认证或 DomainRecord.identityIssuers 中的签发者 | DOMAIN_CERTIFICATION_INVALID / ISSUER_SCOPE_INVALID, 不能只凭机构 DID 登记通过 |
| S02 | IB 签 A 域主体, 或凭证类型/实际披露属性超出 T 认证范围 | ISSUER_SCOPE_INVALID, 不能把越界声明用于授权 |
| S03 | 用 IA 对 IB 的背书或 IB 转授给第三机构替代 T 的直接域认证 | 路径结构/schema 或 DOMAIN_CERTIFICATION_INVALID 拒绝, 仅接受 T 直接认证域机构 |
| S04 | 删除 T 的域认证, 替换根, 使用已撤销/到期/非当前域认证 | 缺字段为 INVALID_SCHEMA, 其余 DOMAIN_CERTIFICATION_INVALID, 无有效身份路径 |
| S05 | 替换 VC 签名, 公钥或算法为 none | SIGNATURE_INVALID |
| S06 | 修改披露值, salt, 重复摘要或省略必需角色 | 披露/schema 拒绝 |
| S07 | 复制他人的 VC, 没有对应持有者密钥 | HOLDER_MISMATCH |
| S08 | 修改受众, 部署, 任务, 资源, 商品或金额 | 请求绑定拒绝 |
| S09 | 重放相同挑战, 包含两个 C 实例并发请求 | 最多一次终态决策/业务效果, 其余重放拒绝 |
| S10 | nonce 正确但 iat 越界, 挑战过期 | 挑战时间拒绝 |
| S11 | 子权限新增动作, 资源或供应商 | DELEGATION_EXPANSION |
| S12 | 子金额大于父金额, 改货币或混用元/分 | schema 或委托约束拒绝 |
| S13 | 子期限提前开始/延后结束, 深度不减 | 委托约束拒绝 |
| S14 | 父剩余深度 0 仍创建子授权 | 管理层及访问校验拒绝 |
| S15 | 用兄弟分支凭证拼接 parentId/digest | PATH_INVALID |
| S16 | 叶子 grantee 与当前 actor 不同 | HOLDER_MISMATCH / PATH_INVALID |
| S17 | 父 grantee 与子 issuer 的凭证或密钥版本不连续 | 路径拒绝 |
| S18 | 预授权根不是 C 签发, 或采购方根不是 A 当前 PA 签发 | ROOT_AUTHORITY_INVALID; 合法 PA 根在正确模式下可通过 |
| S19 | 在过去/尚未开始/正好 exp 时访问 | 期限拒绝; nbf 时允许进入后续检查 |
| S20 | 叶子有效, 但根或中间授权撤销 | 已应用状态后 ANCESTOR_INACTIVE |
| S21 | 叶子有效, 但祖先凭证/公钥/所属域失效 | 身份或祖先验证拒绝 |
| S22 | 轮换密钥后命中旧验签缓存 | KEY_VERSION_STALE, 不能绕过状态 |
| S23 | 策略包正文不匹配链上摘要, 版本倒退 | 所需材料不可用, 拒绝访问 |
| S24 | 伪造客户端 NORMAL, verified=true 或角色 | 不采信; 按可信源决策 |
| S25 | 策略缺属性, 输入类型错误, 求值异常 | schema 或 fail-closed, 不允许 |

## 3 状态, 关联与根授权

| 编号 | 输入或操作 | 验收条件 |
| --- | --- | --- |
| S26 | 节点停在 h, 多次成功读同一块或重启网关 | 超龄后 STATE_STALE, 接收时间不得续期 |
| S27 | 把旧 G1 替换为 G1' 后继续提交旧 G2 | 旧路径仍拒绝; 新 G2' 才可能有效 |
| S28 | 同幂等键不同订单, 或提交低金额引用高价报价 | 冲突/金额不符且无第二订单 |
| S29 | 撤销一支委托, 再访问合法兄弟支 | 被撤销支拒绝, 兄弟仍可通过 |
| S30 | 撤销共同祖先后访问所有分支 | 全部相关路径在规定状态条件下拒绝 |
| S31 | 直接提交合约可接受但资源范围扩张的授权摘要 | 网关必须拒绝, 登记成功不是访问许可 |
| S32 | 超大证据包, 超安全整数, 重复 JSON 键 | 有界解析拒绝, 不崩溃, 不执行业务 |
| S33 | 初验有效, 等待数据库锁后凭证/委托/任务到期 | 最终时间检查拒绝; 不产生订单 |
| S34 | 以相同 chainId 和 genesis 重建网络, 提交旧部署证据 | 新 instanceId 导致部署绑定失败, 正常重启沿用原标识 |
| S35 | 关联时缺一域账户认证或使用错误应用密钥 PoP | 对应域注册机构拒绝, 不产生有效关联 |
| S36 | 单方登记后直接使用关联, 同一域冒充另一域批准 | 关联仍待审批或合约拒绝, 不能变为 effectiveActive |
| S37 | 替换关联端点/承诺/版本/期限, 跨部署或重用 PoP | 绑定或一次性证明检查拒绝, 不能批准不同提案摘要 |
| S38 | 关联审批超时, 关联到期, 端点停用或换钥后查询 | effectiveActive 为 false, 换钥需新关联与证明 |
| S39 | 用关联主体 U-in-B 替代 G0 中的 U 或沿用其角色 | 原主体/凭证/密钥连续性检查拒绝, 不继承访问权 |
| S40 | 撤销关联后访问两端各自独立的合法授权 | 对应关系失效, 独立路径仍按各自身份和授权判断 |
| S41 | 未授权者更换 G2 的 grantee, 或替换后 B₁继续用旧 G2 | 非原 issuer 管理请求拒绝; 已应用替换后旧路径拒绝, B₂需自己签署新挑战 |
| S42 | 初验有效, 等待数据库锁期间越过 policyDeadline/accessDeadline | 最终期限或策略检查拒绝, 不产生订单 |
| S43 | 改 authorizationMode/principalDomain, 混用两模式任务/根/后代 | 请求绑定或模式一致性拒绝, 不降级重试其他模式 |
| S44 | IA 只有身份签发资格却签 BUYER_MANDATE 根, 或 PA 停用后复用根 | 根资格/当前状态拒绝; 有效 PA 根配对允许 |
| S45 | 有效采购方根但 C 拒绝企业/商品, 客户端自报 supplierAcceptance=true | 按 C 可信策略拒绝, 无业务效果 |
| S46 | 改 DID 文档 id, 公钥, 摘要, kid 或仅列密钥但缺要求用途 | DID_DOCUMENT_MISMATCH / DID_KEY_PURPOSE_INVALID |
| S47 | DID 已换钥, HTTPS 仍旧文档或缓存旧文档 | 只接受当前链上锚匹配的文档/公钥, 不回退旧版 |
| S48 | DID 解析指向未登记主机/重定向/不可信 TLS | 解析拒绝, 不通过关闭 TLS 绕过; 允许主机与可信 CA 正例通过 |
| S49 | 无权地址直接发管理交易, 或两笔均已被接受的管理交易使用相同 expectedRevision | 已入块的回退交易 status=0x0, 无登记变化或交付. 有权且版本匹配的交易成功; 接受前冲突与接受后失败的 HTTP 区别另按 S100 验证 |
| S50 | 在读取 G1 与 G2 之间让撤销入块, 另行注入某一固定高度查询失败 | 记录所有调用参数均为同一 h. 失败时不逐项回退到 latest. 采用撤销块后不能放行 |
| S51 | 注入同高异哈希, 节点回退或区块时间超出未来容差 | 进入未就绪态, 停止新决策. 恢复可信且新鲜的头后再服务 |

## 4 报价, 并发与材料交付

| 编号 | 输入或操作 | 验收条件 |
| --- | --- | --- |
| S52 | 改任务商品/数量, 正确重签请求但超 taskSpec 范围 | TASK_SCOPE_MISMATCH; 仅绑定请求不能替代任务限制 |
| S53 | 替换 taskSpec 正文, 与链上摘要不符 | 对象摘要拒绝; 原任务明细配对允许 |
| S54 | C 只启用 RESOURCE_PREAUTHORIZED, 客户端以有效 PA 根改走 BUYER_MANDATE | SUPPLIER_POLICY_DENIED, 不能用可选模式绕过 C 的预授权要求 |
| S55 | 用 B₁在另一任务的 Q800 下单, 或 B₂用 B₁的 Q800 下单 | 自身路径有效且请求重签, QUOTE_SCOPE_MISMATCH, 无订单. 同一主体在本任务重新询价后允许 |
| S56 | 同一报价分别在 validUntil-1 和 validUntil 下单 | 前者允许, 后者 QUOTE_EXPIRED. 各自申请新挑战, 保持身份/任务等其他期限有效 |
| S57 | 两实例用不同挑战同时提交相同订单键, 再用权限内不同报价重复 | 同请求返回同一 orderId, 只有一行订单. 异请求 IDEMPOTENCY_CONFLICT |
| S58 | C 目录价依次设为 100000, 100001 分, 每次先询价再按真实金额下单 | 边界允许, 高 1 分时 AMOUNT_LIMIT_EXCEEDED. 修改目录后仍可引用未过期的原报价 |
| S59 | 询价提交成功而响应丢失, 用新挑战及相同键重试 | 有效期内返回同一 quoteId. 到期后 QUOTE_EXPIRED, 用新键才产生新报价 |
| S60 | 改叶子披露顺序或去掉摘要输入末尾的波浪号, 继续用原 KB | sd_hash 或项目绑定校验失败. 使用精确原始字节的正例通过 |
| S61 | 给同域另一位合法采购负责人签 G0 并引用 U 的任务 | 即使签发者资格正确, grantee 与 task.creator 不同, 根验证拒绝. 以 U 为 grantee 的原根允许 |
| S62 | 丢弃 201 后重取挑战. 再分别使用不存在的 ID, 刚到期的未用挑战, 既消费又过期的挑战 | 丢 201 不产生业务行. 三例依次为 401 CHALLENGE_UNKNOWN, 401 CHALLENGE_EXPIRED, 409 CHALLENGE_REPLAY. 无新增终态决策 |
| S63 | B₁收到询价 200 但 taskId 不同或总价与单价乘数量不符, 另在下单提交后截断 200 | 前两例不发下单挑战. 最后一例保留 OUTCOME_UNKNOWN, 用原键找回原订单. 正常响应配对通过 |
| S64 | 新询价前删去 P1 价格行. 已经取过的有效报价另测同键重试和下单 | 新询价 409 PRICE_UNAVAILABLE, 消费挑战并写拒绝, 无新报价或业务键. 当前策略允许时, 旧询价同键返回原报价, 引用旧报价的新订单按原价可建 |
| S65 | 询价后调高目录价再按原报价下单. 另在询价之后撤销 G1 或将风险调成 ELEVATED | 仅调价时按原价成交. 已应用撤销或新风险时分别报 ANCESTOR_INACTIVE 或 POLICY_DENIED, 各自无新订单 |
| S66 | G1 合法且 Q800 有效, 在不同秒签发两个挑战, 并发提交同键同订单, 用屏障使较早挑战在最终获锁时恰到 expiresAt, 另一个仍有效 | 过期的一方拒绝且未消费, 另一方仍可成功. 恰有一笔订单和一条终态允许决策 |
| S67 | 用 B₁或 A 域管理员登录直接调用订单核账接口. 对照由 C 审计员查同一提交记录 | 无权限返回 403 AUDIT_FORBIDDEN, 不泄露订单是否存在. C 审计员可查历史结果, 报价, 订单, 业务键及挑战行均无变更 |
| S68 | 合法询价只改一个字段: 省略 quoteId, 将金额改为字符串, 或将资源改为订单资源 | 三例均在 schema 阶段返回 400 INVALID_SCHEMA, 无业务行, 原挑战未消费, 同挑战提交原合法封包仍可通过 |
| S69 | 应用 PoP 正确, 管理地址证明由另一账户签署或绑定另一会话 | 本域注册机构拒绝登记. 双证明均有效时仍由注册机构签登记交易 |
| S70 | C 或 PA 读到已确认任务, 但 A 返回的 taskSpec 被改. 另以普通同域服务向 A 取明细 | 前者摘要失败, 后者交付权限拒绝. 签发方不签 G0, 无登记或发件行 |
| S71 | RP 用 PA 签根, 或 BM 用 C 签根. 另保留合法 BM 根而从发给 U 的包去掉 PA 凭证 | 错误的管理调用者被合约拒绝. 即便有权者登记了与错误签名对应的摘要, 接收端验签和根资格也必须拒绝. 缺 PA 材料时即使合法根已成功登记, U 不入钱包, 不生成 G1 |
| S72 | B₁提交的最小出示缺 T 对 B 域/IB 的认证或 role, 或 A₁用另一分支的 parentDigest 申请 G2 | A₁在签名前拒绝, G2 数不变. 正确的域认证和父路径可产生一份 G2 |
| S73 | 把原包送错钱包, 伪造发送域, 或按同一收件键重投改变 taskSpec 的包 | 前两例 MATERIAL_FORBIDDEN, 后一例在已有回执时 DELIVERY_CONFLICT. 原钱包记录不变, 错误钱包为空 |
| S74 | B₁收到完整上游包但钱包叶子凭证不符或无对应私钥. 另在 G2 入库后撤销 G1 再申请访问 | 前者不置 MATERIAL_READY. 后者已存回执仍可查, 含已应用撤销的快照必须拒绝执行 |
| S75 | 在 BM 中给 B₁混入 RP 的 G1, 或删去 U 的祖先凭证 | 即使所有剩余 JWS 逐份验签成功, B₁验收模式/任务/父摘要或凭证引用失败, 不形成新收件回执 |

## 5 共同根与域资格

| 编号 | 输入或操作 | 验收条件 |
| --- | --- | --- |
| S76 | 用自建 T' 签合法外观的域认证, 或修改 T 域认证正文后沿用原签名 | DOMAIN_CERTIFICATION_INVALID 或 SIGNATURE_INVALID, 预置根不能由证据包指定 |
| S77 | 将域认证中的 domainDid, 管理员, 注册机构, 机构 DID/密钥版本或范围改成与同块登记不同的值 | 即使由测试 T 真实签名也因正文/登记不一致而拒绝; 同字段一致正例通过 |

| --- | --- | --- |
| S100 | 普通身份换钥先提交已过时 revision 的新操作, 再用屏障使两笔不同操作键的合法换钥均通过同一版本预检, 返回 202 后才广播/确认交易 | 首例 HTTP 409 STATE_CHANGED, 无待提交操作及交易 nonce 分配. 后两笔各有 operationId, 一笔成功, 另一笔回退. 查询均为 HTTP 200, 成功为 CONFIRMED/null, 失败在取得实际回退数据后为 FAILED/STATE_CHANGED, 保留原 txHash/receiptStatus=0x0/区块. 不补发原 POST 的 409, 失败不覆盖胜者的新钥且不交付失败材料 |
