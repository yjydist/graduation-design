# 实现导航

这里记录原型的实施契约. 从登记主体到创建订单, 分别验收管理交易确认, 证据送达持有者, C 对本次请求定案.

| 实现顺序 | 编写或查阅什么 | 对应设计 |
| --- | --- | --- |
| 1. 部署与登记 | [技术栈](技术栈.md)说明组件选择, 节点控制权和部署冻结条件. [部署与链上登记](部署与链上登记.md)列出 T 根预置, 三域/机构认证引导, 部署标识, 合约写权限及交易确认和重试规则, 第 3 节定义身份状态与管理账户恢复. [管理响应](REST接口与响应码.md#2-rest-接口)区分接受前 HTTP 拒绝及接受后 operation 失败, [固定编码](协议编码与测试向量.md#14-did文档-公钥与凭证上下文编码)统一 DID/JWK/凭证上下文. | [三域分工](../design/采购场景与总体设计.md), [跨域身份与信任](../design/跨域身份与信任.md) |
| 2. 交付签名材料 | 按[钱包交付顺序](证据交付与网关执行.md#1-签名材料的逐跳交付)登记和投递. 域认证, 本域身份凭证, 委托, 任务字段及字节摘要查[协议编码与测试向量](协议编码与测试向量.md). | [根授权与子授权](../design/委托授权与策略.md) |
| 3. 验证本次请求 | 按[固定高度的读取器](证据交付与网关执行.md#2-固定高度的读取器)装配 T 根, 域资格及业务材料, 按[策略输入与数据约束](策略输入与数据约束.md)构造 OPA 输入并校验策略包. | [请求认证与状态一致性](../design/请求认证与状态一致性.md) |
| 4. 提交订单 | 客户端按[REST 接口与响应码](REST接口与响应码.md)发挑战和订单请求, 按[nonce 编码](协议编码与测试向量.md#21-挑战-nonce-编码)原样绑定挑战, 用[请求编码向量](协议编码与测试向量.md#3-请求与可复算向量)核对摘要. C 按[订单事务](证据交付与网关执行.md#3-c-如何提交订单)在锁后用当前环境重新求值, 依[数据库唯一性约束](策略输入与数据约束.md#2-数据库唯一性与审计字段)定案. | [请求绑定与锁后复核](../design/请求认证与状态一致性.md) |
| 5. 恢复未知订单 | 订单已提交但响应丢失时, 按[订单核账](订单核账.md)保留原业务键, 查明创建决策, 复核历史状态. | [SG6 审计目标](../design/威胁模型与安全目标.md) |

字段和测试向量在编码文档维护, HTTP 行为在接口文档维护, 持久化约束在策略与数据文档维护. 变更契约时核对[设计依据](../design/AGENTS.md)和[实验用例](../experiments/验证用例.md), 明确接口约束和示例值的适用条件.
