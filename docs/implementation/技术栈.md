# 技术栈与部署选择

C 需要回答的是同一高度上的三个问题: B₁的密钥是否有效, 上级 G1 是否已撤销, 下级 G2 是否仍绑定这条路径. 选用 Besu, 因为网关可以直接为每个合约查询指定相同块号, 只读这次请求引用的记录. 这项选择依据读取语义, 性能由实验测定. [Besu eth_call](https://docs.besu-eth.org/public-networks/reference/api/eth/execute#eth_call).

## 1 网络与治理

| 决定 | 选定配置 | 可检验的边界 |
| --- | --- | --- |
| 业务域 | A 采购, B 协作, C 供应 | PA 属于 A. C 决定是否接受订单 |
| 身份权威 | 三域共同预置 T 根, T 认证域和 IA/IB/IC 的签发资格 | T 为独立身份基础服务, 各域证明本域主体身份. T 不决定采购权限, 不因认证角色取得共识投票权 |
| 共识 | 私有 genesis, 固定 4 个 QBFT 验证节点 | 四节点中至少三个参与确认. 停一节点测继续出块, 停两节点测停链与拒绝 |
| 控制权 | A/B/C 各配置一把验证密钥, 第四把由实验运维保管 | 第四节点没有业务角色. 同机四容器共享宿主与运维权限, 实验结论限于节点故障. 机构级容错需要独立控制与故障域证据 |
| 准入 | 各节点配置一致的节点和账户许可名单, RPC 限域内可信服务 | 合约另按调用地址, 机构角色与对象归属检查每笔写入 |
| 时间 | 预设出块周期 1 秒, 空闲时持续出块, 部署验证须核对实际配置和间隔 | 默认状态年龄上限 5 秒. 停链后重读旧块不能延长使用时间 |
| 读节点 | C 连接自行管理的可信 Besu RPC, 启动核对链和合约 | 记录裁剪配置, 留足在途查询窗口. 实验审计节点保留可读的历史状态 |

QBFT 容忍一个拜占庭验证节点的前提是至少四个验证节点, 且满足协议的网络和故障假设. 网络成员资格, 验证节点签块资格, 合约写入权限和业务授权分别管理. [QBFT 配置及阈值](https://docs.besu-eth.org/private-networks/how-to/configure/consensus/qbft), [许可配置的作用范围](https://docs.besu-eth.org/private-networks/concepts/permissioning).

## 2 组件与密钥

| 组件 | 选择 | 用途 |
| --- | --- | --- |
| 链与合约 | Besu, QBFT, Solidity AuthRegistry | 按角色登记摘要, 版本及状态, 原子替换委托 |
| 管理交易 | Go Ethereum 客户端, ABI 绑定, secp256k1 账户 | 签管理交易, 查回执, 在指定块执行只读调用 |
| 域服务 | Go net/http, 域间 mTLS | T 与 A/B/C 独立服务和数据库, 按登录角色选择管理钱包 |
| 应用身份 | did:web, VC, SD-JWT, ES256/P-256 | 登记文档摘要和密钥用途, T 签域认证, IA/IB/IC 签本域 VC, 业务方签委托和请求挑战 |
| 编码 | jwx/v3, SHA-256, JCS | 原始签名字节验签, 规范 JSON 计算业务摘要 |
| 策略与数据 | 内嵌 OPA/Rego, PostgreSQL | C 链下求值, 事务消费挑战并记录报价/订单 |
| 部署与测量 | Docker Compose, Go 测试及负载驱动, Python | 重建夹具, 记录每笔请求, 管理交易和资源开销 |

T 的根 DID/应用公钥/文档摘要及管理地址通过受信渠道分发并与 RootRecord 固定绑定, 与测试 TLS CA 分开. T 根 DID 文档随部署材料预置本地并核对摘要, T 的服务或 DID 主机离线时不影响该固定根的本地验证. 同一部署固定 T 根密钥, 根替换需要新部署. 域身份机构换钥须 T 重新认证. T 应用私钥, T 管理交易密钥及各域密钥分开保管; T 停服不妨碍已有有效域认证的本地验签与新鲜状态核验.

DID 主机只允许已登记域名和受信测试 CA. 解析后按当前块的摘要, keyId, 版本和用途核对文档. 文档摘要使用完整 JSON 的 JCS UTF-8, 应用公钥固定 65 字节 P-256 非压缩点, JWK 只使用公共坐标, 凭证上下文使用固定数组及内联扩展; [字节编码与向量](协议编码与测试向量.md#14-did文档-公钥与凭证上下文编码)为共同契约. 验证节点密钥, 管理交易密钥和 DID 应用密钥分别生成与保管. [DID Core](https://www.w3.org/TR/did-1.0/), [did:web](https://w3c-ccg.github.io/did-method-web/), [SD-JWT](https://www.rfc-editor.org/rfc/rfc9901.html).

## 3 部署冻结条件

在目标架构实机验证成功后, 固定 Besu 镜像 digest, genesis, 许可名单, T 根锚和认证配置, 验证者地址及控制方, Solidity 编译器设置和运行时代码哈希, Go 模块, 数据库版本与容器资源上限. 保存 DID/JWK 及 nonce 编码向量, 固定 VC 基础上下文本地副本摘要, 生成本部署真实签名向量. 验证原交易实际回退数据的读取/解码, 原因暂不可得时按 TRANSACTION_REVERTED 处理, 不把失败 receipt 当作具体原因. 记录节点历史状态保留范围及实测空块间隔. 业务准入使用 OPA, 每次请求在固定高度读取并在锁后求值. 缓存复用须满足固定块哈希, 材料及密钥版本约束, 不能省略动态条件复核. 部署身份计算和成功回执判据见[部署与链上登记](部署与链上登记.md).

## 4 账本配置与编译约束

| 项目 | 选定配置与约束 |
| --- | --- |
| Besu | 26.11.0, linux/arm64, digest `sha256:3d6ac0368d449c13c4ba075acac90d6b96afa5b3113295385d88c4d5122c8808` |
| 共识/状态 | chainId 20261104, Berlin, 4 QBFT 验证者, 周期 1 秒, request timeout 4 秒, epoch 30000, FOREST/FULL, 不启用历史裁剪 |
| 资源 | 单容器 2 CPU/1280 MiB, JVM 256-512 MiB. 同机部署的控制边界见第 1 节 |
| 编译器 | solcjs 0.8.30, optimizer=true/runs=200, viaIR=true, evmVersion=berlin. 编译输入与 genesis 的 EVM 规则必须一致 |
| Go | Go 1.27.3, Go Ethereum v1.16.9, 依赖由根目录 go.mod/go.sum 锁定. macOS 纯 Go 构建使用 CGO_ENABLED=0 |
| 合约构造 | 固定 T 根和受信部署清单中的 A 域/U 任务创建资格, 启动核对部署标识和运行时代码哈希 |
| 交易取证 | 原交易 callTracer, 同块执行不一致时按原块哈希/完整顺序/原位置严格取证, 无可信原因保持通用失败 |
| 读取 | 全依赖固定同一高度, 默认 5 秒状态年龄上限/1 秒允许时钟偏差的双时钟检查, 最高已见头按 deploymentId 保存检查点 |

1 秒出块周期不构成实际间隔的性能保证, 也不替代 5 秒状态年龄检查. 实际间隔须由运行时的连续空块时间戳测量.
