# E1 采购功能闭环

## 1 研究问题与范围

在共同身份根 T 下, 资源方预授权和采购方发起委托能否各自完成从登记, 签发, 逐跳交付到询价和模拟订单的闭环? 用 F01-F16 检查身份关联, 两种根的权源, C 的独立准入和实际业务副作用. [采购场景](../../docs/design/采购场景与总体设计.md), [F01-F16](../验证用例.md#1-采购闭环).

## 2 对照与变量

- RP 由 C 签发 G0, BM 使用有业务资格的 PA 签发 G0. 两种模式使用独立任务及授权 ID, 保持商品, 数量, 金额, 委托深度及有效条件可比.
- 每种模式都运行 800 元成功, 1200 元原价拒绝和 Q1200 改报 800 元的负例. 同键异摘要冲突使用两笔限额内的 Q800/Q900, 使金额校验与幂等冲突可分别判定.
- 记录实际状态配置. 需要三组对照时, 按 [C0/B0/B1 定义](../实验计划.md#1-实验地图与同语义对照)配置. 功能判定使用相同业务条件.

## 3 输入与准备

从干净实例及空钱包开始, 预置 T 根, 域机构和真实签名材料, 按用例引导登记, 双域关联和签发. 每种任务的 G0/G1 上限为 5000 元, G2 收缩到 1000 元, 深度为 2/1/0. 按[共用复现约定](../实验计划.md#共用复现约定)固定构建, 策略和夹具, 配置真实 LLM.

## 4 执行与采样

1. 按 F01-F04 完成登记及信任核对. F05 由真实 LLM 驱动的 A1 调用 MCP 钱包工具生成并交付 G2, B1 在 F06/F07 调用同一工具层发起询价及下单. 记录模型, 推理耗时, 工具调用和请求关联.
2. 按 F08-F16 检查同键重试, 决定可解释性, BM 独立成立, C 独立拒绝, DID 绑定, 模式绑定, T 离线, 资格续发或轮换, 以及证据绑定. F11 保留 C 拒绝合法 PA 根的配对用例.
3. 保存用例, 请求, 挑战, 决定, 报价, 订单及业务键的关联, 区分钱包工具结果, 网关状态来源及主库核对. 以 HTTP 和主库检查表交叉核对实际效果.

## 5 判据与缺测

F06 每种根各得一份真实 Q800 和一笔订单, 询价和下单共四次往返, 无业务链上写入. F07 超额原价订单被拒, Q1200 改报应先触发 `AMOUNT_MISMATCH`. 拒绝侧无新增订单或相应订单业务键. 同键合法重试返回原订单, 同键异摘要冲突. 其余判据逐项查 F01-F16.

工具未调用, 模型请求失败, 环境未就绪和主库核对失败分别记录原因. F07 只有网关实际收到超额下单请求且通过拒绝判据时, 才计为完成服务端负例验证.

## 6 结果表和图

按运行 ID 和 RP/BM 报告 F01-F16 通过, 失败或缺测, 配套展示模型会话, 工具调用次数, 报价和订单行数. 选取一条从 G2 交付到订单定案的轨迹, 标注对应请求与决定. 按运行 ID 引用清单, 脱敏模型轨迹, 请求和主库记录.
