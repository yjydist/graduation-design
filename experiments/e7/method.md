# E7 故障与并发

## 1 研究问题与范围

状态读取, 排序, 区块交付, 业务锁或响应发生故障时, 系统能否按原期限拒绝, 保持订单唯一性并恢复核账? 注入仅作用于隔离测试环境. 同机停容器的结论限于节点级故障. [请求认证与状态一致性](../../docs/DESIGN.md#4-请求认证与状态一致性), [订单核账](../../docs/IMPLEMENTATION.md#7-订单核账).

## 2 对照与变量

按以下注入点改变单一条件, 保留相同业务输入的正常对照与恢复样本. 分别对客户端到 C, Peer 区块交付及排序通信施加单向延迟 0/20/100 ms, 丢包 0/1/5%. 使用确定性工具控制时序, 与 [E3](../e3/method.md)的真实智能体响应丢失场景交叉核对.

## 3 输入与准备

准备真实授权, 报价及交易主库. 同键并发使用同一报价和业务键, 其余条件按场景控制, 记录各实例的视图和探针. 各故障场景从已知正常检查点开始. D0 的提交校验码, 块流和状态读取用于定位故障, E7 另核对订单, 挑战, 业务键及核账结果.

## 4 执行与采样

| 注入点 | 观察与判定 |
| --- | --- |
| 在同一读取事务的两次依赖读取之间应用 r | 整次装配仍取 h. 下次读取采用 r 或更高后看到撤销. 缺依赖, 缺块或历史失败时整次拒绝 |
| 分别停止一个和两个 SmartBFT 排序节点 | 保持 Peer 可用. 停一记录新探针 VALID 与采用时刻, 停两等待在途收敛后记录无新确认及最后高度. 原期限到期时 STATE_STALE, 恢复后补块并采用新探针 |
| 中断 C 的 Peer 或完整区块交付 | A/B 仍可背书并确认交易. 记录 C 最后应用高度, 原探针期限和首次拒绝. 恢复时核对检查点并补齐区块, 由本进程有效新探针重新就绪 |
| C 甲采用 r, C 乙暂用 h<r | 保持同一报价和有效条件, 分开记录两实例探针和最后允许/首次拒绝. 采用 r 后拒绝, h<r 的决定还须早于原期限. 同键最多一笔订单 |
| 等业务锁时应用撤销或越过截止 | 先推进共享检查点再释放业务锁, 检验锁后比对和整次重验. 到达挑战, 报价, 资格或探针期限均拒绝. 同挑战最多一个终态决定 |
| 初验后风险升级 | 屏障使观测器在环境行锁取得前提交 ELEVATED/BLOCKED, S91 验证锁后重跑 OPA. S92 用实际时间核对期限. 共享锁取得后的更新等本事务结束 |
| 管理交易结果未知或授权交付响应丢失 | 按原 txID 或原已签字节恢复. S100/S101 分别核对受理前 409, 受理后 202/查询结果, PENDING 和通用阶段码. 重播重复码不改变原结果. VALID 且交付资格仍有效后只重投原包 |
| 订单提交后丢响应, 随后撤销 G1 | B 停发, C 用 R/k/H 和挑战清单找创建决定, 对照历史 h/r 与原期限, 给出 CREATED/NOT_CREATED/UNKNOWN 和历史完整性 |
| 风险观测停更, 策略包缺失或墙钟异常 | 记录 CONTEXT_STALE, POLICY_UNAVAILABLE 或状态异常. 停止创建订单, 恢复后复核策略锚及实际时效 |

未知订单恢复从只有 R/k/H 和挑战清单的状态开始. 按相应 [F/S 用例](../验证用例.md)记录注入点, 初始与恢复高度, 原探针, 响应码, 业务决定及提交副作用. 用新挑战重试同键时, 核对原订单和新增行数. 追踪恢复后补齐状态和有效新探针的时点.

## 5 判据与缺测

逐条满足上表的拒绝和恢复判据. 拒绝或过期请求的副作用及同键订单唯一性以主库和挑战消费记录为准. 响应未知按订单核账判 `CREATED`, `NOT_CREATED` 或 `UNKNOWN`, 保留历史完整性和适用缺测原因.

## 6 结果表和图

按故障, 实例及注入参数列出预期和实测拒绝, 恢复时点, 业务行数和核账. 时间线关联注入, 视图高度, 探针期限, 实际决定和恢复事件, 标明运行 ID 和原始文件.
