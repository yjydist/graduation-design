# E8 账本与通信开销

## 1 研究问题与范围

链下验证的客户端交互与计算耗时有多少, 账本, 探针, 区块流及视图处理分别承担多少成本? 用确定性工具分开测量登记准备, 客户端出示, 后台交易和节点资源. [链上与链下分工](../../docs/DESIGN.md#1-采购场景与总体设计).

## 2 对照与变量

用 C0/B0 对照状态提供及后台开销, 用 B0/B1 对照验签复用的适用指标. 保持两种授权根的业务条件配对, 报告各自证据及 C 本地服务资格依赖. 分别测空闲和负载状态. 按[共用对照](../实验计划.md#1-实验地图与同语义对照)设置适用的 `A-FULL` 和 `A-REUSE` 材料配置.

## 3 输入与准备

按 [F01-F06](../验证用例.md#1-采购闭环)隔离 T 引导, 各域登记, C 服务准备和实际访问. 固定并记录拓扑, 节点控制方, 镜像, 时基, 链码及运行配置. 对负载条件引用 [E5](../e5/method.md)的实际到达参数. 各类管理操作至少测 30 个独立对象.

## 4 执行与采样

1. 单列 T 引导与域认证, 本域身份登记, 授权, 轮换, 撤销, 替换及 C 服务准备成本. 对每笔记录提案生成至背书, 首次广播至排序接收和可信 Peer 校验, 可信 Peer 到达至视图提交各阶段的时间, 字节与结果.
2. 在空闲及负载时测探针发送, 确认, 采用率, 探针和区块流的消息数与字节, 视图事务开销及检查点冲突重验率. 按秒采集 Peer/Orderer/数据库的 CPU, RSS, 网络, 磁盘和可观测队列.
3. 单列客户端挑战和执行两次往返及每次出示大小. 将请求, 原 txID, 排序接收, 可信 Peer 结果, 视图推进及资源采样按运行 ID 和时点关联.

## 5 判据与缺测

排序接收成功和 Peer `VALID` 分列. 只对直接可观测的内部阶段单独计时. 失败, 无确认和未观测字段按[共用复现约定](../实验计划.md#共用复现约定)记录并附原因. 成本结论限定在实际运行拓扑, 负载和样本量.

## 6 结果表和图

按配置及操作类别列独立对象数, 阶段耗时和字节, 客户端通信, 探针开销与节点资源, 对空闲和负载分别汇总. 用运行 ID 关联 `operations.csv`, `communications.csv`, `resources.csv` 等原始文件, 用图展示客户端与后台阶段各自的实际开销.
