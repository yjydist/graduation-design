# 变更提案

## 为什么

本变更将已确定的 Besu QBFT 和固定高度读取落实为可运行的最小账本切片. 开始 MVP 开发前, 需要首先证明同一份委托在撤销前后可按指定高度读出不同状态, 并在停链导致状态超龄时停止提供可用状态结论.

## 变更内容

- 新增可重复启动的四验证节点 Docker Compose 网络, 配置节点及账户许可, 持续空块, 受限 RPC, 数据持久化和显式重建流程.
- 新增 Solidity AuthRegistry 的最小登记切片, 覆盖不可变 T 根, 部署实例标识, RP 夹具必需的域/身份/凭证锚/任务和 G0/G1 登记及撤销. 实现所用入口的真实权限和版本检查, 不设置任意写入的夹具后门. U 的 A 域任务创建资格在受信部署清单及合约构造中固定.
- 新增 Go 部署及验证命令, 使用真实管理账户签交易, 核对回执, 保存原交易回退证据, 在原因不可得时保留通用失败结果.
- 新增按固定高度读取多项依赖的读取器, 分别验证历史状态和在线状态新鲜度, 禁止失败后按单项退回 latest.
- 新增撤销前后对照, 无权写入, 版本竞争, 指定高度查询失败和停一/停两节点的可重复验证, 输出结构化原始证据.
- 交付运行说明并同步项目进度及 D0 验收映射. 本变更仅覆盖 D0 最小网络里程碑, 不标记 D0 最小协议或 D0-M2 MVP 完成.

## 能力

### 新增能力

- `permissioned-ledger`: 四节点许可账本的启动, 部署绑定, 持久化及节点故障行为.
- `authorization-registry`: T 根约束下的最小 RP 登记路径, 按调用者及版本控制写入, 委托撤销和交易结果证据.
- `fixed-height-state`: 同一高度读取依赖, 历史状态复查, 在线新鲜度检查及查询异常时停止给出可用结论.

### 修改能力

无. 当前尚无已归档的 OpenSpec 主规格.

## 影响

- 拟新增 `infra/besu/`, `contracts/`, `cmd/ledgerctl/`, `internal/ledger/` 及 Go 模块/合约编译配置. 具体分工见 [设计](design.md), 验收见 [任务](tasks.md).
- 使用 Besu, Docker Compose, Solidity 和 Go Ethereum 客户端, 在目标架构实测后锁定镜像 digest, 编译器设置和 Go 依赖. 实际锁定材料和原实例/干净重建结果见[D0 证据索引](../../../../infra/besu/evidence/README.md).
- 实施时更新 [项目入口](../../../../README.md), [任务安排](../../../../TODO.md), [技术栈](../../../../docs/implementation/技术栈.md), [部署契约](../../../../docs/implementation/部署与链上登记.md), [网关执行规格](../../../../docs/implementation/证据交付与网关执行.md) 及必要导航, 标明已实现范围和未实现部分.
- 不包含 T/A/B/C HTTP 服务, did:web 在线解析, 完整 ES256/SD-JWT 验证, OPA, 数据库订单事务, BM 根, G2 业务闭环, 缓存或前端. 链上锚使用明确标记的合成材料, 不作为真实凭证验签通过的证据.
- 同机四容器仅支撑节点故障观察, 不作为机构独立控制或拜占庭攻击实测的证明.
