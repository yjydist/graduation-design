# 实施任务

本清单只对应 [提案](proposal.md) 的 D0 最小网络范围. 进度以任务勾选为准, 规划制品通过校验不表示原型已经运行. 已完成部分的证据见[网络说明](../../../../infra/besu/README.md)和[基础合约说明](../../../../contracts/README.md). 行为依据为 [许可账本](specs/permissioned-ledger/spec.md), [授权登记](specs/authorization-registry/spec.md) 和 [固定高度状态](specs/fixed-height-state/spec.md).

## 1. 工程骨架与网络

- [x] 1.1 建立 Go 模块, `cmd/ledgerctl/`, `internal/ledger/`, `contracts/` 和 `infra/besu/` 的最小骨架, 确认 Go 命令可构建且模块依赖可解析; 不新增 Makefile 或文档检查脚本.
- [x] 1.2 实现本地实例初始化, 分离四把验证密钥, T/域/主体管理密钥及 P-256 应用密钥, 生成预充值和许可配置, 将私钥/数据/构建产物加入忽略项; 验证公钥和地址可复算, 普通重启不会重新生成实例材料.
- [x] 1.3 实现四节点 Compose, 一致 genesis, 持续空块及受限 RPC, C 节点作为首个读取节点; 在目标 arm64 环境实际启动并保存四验证者, 相同链身份及至少 10 个连续空块的观测, 记录镜像 digest 和节点配置.
- [x] 1.4 验证未许可节点和未许可账户被拒绝, 关闭后重启仍保留块和密钥; 在 `infra/besu/README.md` 记录资源需求, 控制方, 实际空块间隔, 启停和显式重建命令, 按文中命令完成一次网络重启.

## 4. 管理交易跟踪和回退证据

- [x] 4.1 实现单操作者独占锁, 账户 nonce 串行分配, 广播前保存原始签名交易, 回执核对与重启恢复; 测试广播或回执响应暂不可见时保持原 txHash/PENDING, 恢复后只查询或重播相同字节, 不生成第二笔操作.
- [x] 4.2 从已许可且有余额的无权账户显式提交足够 gas 的撤销交易, 取得 status=0x0 回执并查询状态未变; 在目标镜像实际调用原 txHash 的 `debug_traceTransaction`, 核对交易位置并保存/解码 custom error, 验证错误与原交易对应.
- [x] 4.3 实现 trace 缺失/截断/解码失败的 FAILED/TRANSACTION_REVERTED 分支, 用可控故障测试恢复后只补原因不改失败终态; 输出文档示例明确 receipt 不含具体原因, 不使用 latest 或父块独立模拟猜失败码.
- [x] 4.4 使用两笔相同 expectedRevision 的独立合法撤销交易制造竞争, 验证一笔成功另一笔回退, 最终状态仅递增一次, 两份原始交易/回执/回退证据均保留; 单交易 trace 与回执不一致时, 验证按原块哈希/完整交易顺序/原位置绑定的整块 trace 回退及失配拒绝.
