# 文档职责设计

## Context

三份 `docs/` 导航都包含 D0 的覆盖情况. 实现契约中也有混写, 例如技术栈把选定配置和空块间隔观测放在同一表格, 网关契约把快照语义和复跑命令放在同一页. D0 的任务, 核验结论, 可追溯证据和运行命令已有维护位置. 变更动机见[提案](proposal.md).

## Goals / Non-Goals

- 设计可单独阅读, 能从需求追踪到机制, 技术契约和实验判据. 阶段状态和验收结论变化时, 设计正文和导航无需随之更新.
- 进度读者能从根 `README.md` 进入 `TODO.md`, 查到阶段状态, 适用设计, 对应任务和验证证据.
- 整理限于文档职责和内容归位. 机制, 协议行为, 配置约束, 实验判据和历史验证结论保持原义.

## Decisions

### 按内容职责确定更新位置

| 位置 | 维护内容与更新时点 |
| --- | --- |
| `docs/` 正文和导航 | 设计决策, 适用边界, 实现契约, 技术配置, 测试向量, 实验方法和判据. 设计或契约变化时同步核对相关文档. 导航按主题索引这些材料. |
| 根 `AGENTS.md` | 定义各处的职责, 更新时点和引用规则. 项目结构说明随职责变化更新. |
| `openspec/specs/` | 维护已接受的能力规范和场景. 能力要求变化时按 OpenSpec 流程更新. |
| `openspec/changes/` 及归档 | 记录单项变更的理由, 设计, 任务和核验结论. 活动变更随实施和核验更新, 归档保留当时的记录. |
| `TODO.md` | 维护粗粒度阶段状态, 下一步和退出条件. 阶段状态或退出条件变化时更新, 详细情况引用对应变更和证据. |
| 根 `README.md` | 介绍项目, 提供设计, 进度和运行入口. 入口变化时更新链接, 阶段状态集中在 `TODO.md`. |
| 既有模块运行说明和证据目录 | 模块说明维护可复跑命令及其前置条件. 运行证据保存实例配置, 原始数据, 实际结果及失败样本, 由变更验证记录引用. |

任务和验证记录可以引用 `docs/`. `docs/` 可引用其他设计资料, 任务书, 论文和技术规范. `docs/` 的正文和导航均移除指向 `TODO.md`, 变更实施任务, 验证记录, 证据索引及含进度内容的模块 README 的链接. 单纯把状态段落替换成进度链接仍会让设计导航承担进度入口的职责, 因此统一从根 README 导航.

### 保留技术语义, 将实际状态归入现有记录

- 技术栈区分选定的 1 秒出块配置, 5 秒状态年龄上限, 镜像与编译设置等技术选择, 以及单次空块间隔观测和当前安装情况. 保留配置语义, 复用证据索引下的原始观测. M1/M3 排期由 `TODO.md` 承载, 既有逐请求读取, OPA 和锁后求值等约束继续留在设计中.
- 部署与网关契约保留受信部署清单约束任务创建资格, `fresh` 只表示快照新鲜度, 以及原交易回退取证和通用失败码的适用条件. 将同块 trace 与回执失配写成触发整块取证的技术条件. 实测样本和当前实现的覆盖情况由既有运行说明和证据记录承载.
- 将编码文档和用例中的阶段标签改写为技术条件, 例如以 U 直接访问时的证据要求和部署清单固定上下文摘要替代排期用语. 将 D0 复跑命令归入相应的既有模块运行入口, 已有命令直接复用. 保留合成材料的设计用途及验证边界.
- `docs/experiments/` 保留实验输入, 方法, 测量口径和预期结果. D0 实际覆盖范围, E6/E7 执行状态及合成材料的实际使用情况由 D0 验证记录和证据索引说明. TODO 只保留阶段摘要和跳转入口.

## Risks / Trade-offs

- 混写段落中可能同时包含授权边界和完成情况. 逐句区分系统约束, 实施状态及单次运行事实, 核对重写前后的权限, 阈值和判据.
- 清理旧链接后, 读者需要从根 README 进入 TODO 查 D0 的实施和验收. 实施时逐跳验证 TODO 可到达归档任务, `verification.md`, 证据索引和受版本控制的原始样本, 并核对归档的 D0 范围与订单级 E6/E7 的区别.
- 改写或移动标题可能使跨文档锚点失效. 同步核对本次修改影响的相对链接和章节锚点, 保留历史归档和证据文件.
