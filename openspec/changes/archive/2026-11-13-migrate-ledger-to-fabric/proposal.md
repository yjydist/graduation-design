# 变更提案

## 为什么

导师已明确使用 Hyperledger Fabric 作为联盟链技术栈. 现有 D0 依赖 Besu 的交易回执, 固定块查询和空块时间, 须在实现采购闭环前用 Fabric 的背书, 提交校验及区块交付语义重建账本基线. [毕设要求](../../../毕设要求.md).

## 变更内容

- **BREAKING** 使用单通道 Fabric 3.1.x 网络, A/B/C 各运行一个 Peer, A/B/C 与实验运维分别控制四个 SmartBFT 排序节点. T 以独立客户端身份提交域认证. 三域共同批准链码定义和部署根, 日常登记交易由三域任意两个组织背书.
- **BREAKING** 用 Go 登记链码及 Fabric Gateway 重建 D0 的 T 根, 域/机构, 身份与凭证锚, U 任务, RP G0/G1, 撤销及原子替换. 以已认证的客户端证书匹配登记角色, 以读写集版本检查保护并发更新, 以 Peer 的有效提交结果确认管理操作.
- **BREAKING** 从 C 的 Peer 完整区块流按序应用有效交易, 原子维护授权状态, 历史记录和区块检查点. 在线读取使用一份一致视图, 由同通道提交的探针限定使用期限. 历史核账按原高度重建.
- 用干净部署, 真实 Fabric 管理交易及明确标记的合成应用材料验证 D0. 重新定义部署标识, 管理证书控制权证明, 原交易证据及撤销时序. 切换后以新部署标识生成夹具和签名向量.
- **BREAKING** Fabric 成为唯一账本实现. 从当前项目移除 Besu 命令, 网络配置, Solidity 合约, 专用依赖和原验收证据.

## 能力

### 新增能力

### 修改能力

- `permissioned-ledger` 定义 Fabric 通道准入, Peer/排序节点职责, 部署身份, 排序故障与可复现运行.
- `authorization-registry` 定义调用者证书与登记角色的绑定, 依赖及版本检查, 原子替换和管理交易结果.
- `fixed-height-state` 定义从已提交区块生成同一高度的视图, 按高度历史复查, 探针期限及续读恢复.

## 影响

- 新建 Fabric 网络及 Go 链码入口, 由 `ledgerctl` 统一提供 Fabric 部署, 登记及读取. 锁定 Fabric 镜像, Go 链码及 Gateway 依赖, 并保存新的 D0 运行证据.
- 同步 [毕设要求](../../../毕设要求.md) 的技术路线, [设计导航](../../../docs/design/AGENTS.md), [实现契约](../../../docs/implementation/AGENTS.md), [实验计划](../../../docs/experiments/实验计划.md) 和 [验证用例](../../../docs/experiments/验证用例.md). 以 Fabric 提交与视图采用时点重写 E6/E7 判据, 将 E4/E5/E8 的后台成本纳入对照.
- 本变更的实施退出条件为 Fabric D0 账本切片及文档同步. 真实 DID/VC 验签, RP/BM 采购闭环, OPA 与订单事务, 正式业务实验按 [阶段任务](../../../TODO.md) 中各自的退出条件推进.
