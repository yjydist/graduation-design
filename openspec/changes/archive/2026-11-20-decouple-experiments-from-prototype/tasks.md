# 实施任务

依据 [设计](design.md) 和 [三组采购基线规范](../../specs/reproducible-procurement-experiments/spec.md) 核对迁移结果.

## 1. 迁移基线并切断原型依赖

- [x] 1.1 固定迁移前的基线构建, 参考运行和种子. 记录 12 个订单的计划, 判定和主库副作用, 以及夹具摘要, 共同登记回读和失败留证的现有核对点.
- [x] 1.2 将基线夹具的任务标识和数量作为明确的业务输入, 通过原型通用登记和装配能力应用. 验证默认部署, 登记和钱包装配路径, 核对传入的基线任务能以原交易回读.
- [x] 1.3 将三组编排, 固定输入, 配对判定, 证据导出及对应测试迁入 `experiments/baseline/`, 接入 `mise run experiment:baseline`. 用离线测试核对三组配置, 入口参数, 独占实例和数据库, 原始字段以及准备失败, 挑战失败和执行 503 的留证与退出状态.
- [x] 1.4 用迁移后的固定构建与同一种子运行两个干净实例. 每轮核对 12/12, 两种状态来源的共同登记回读, C0 快照复核, B0/B1 原探针, B1 静态验签命中和动态拒绝, 以及主库订单副作用. 与参考运行比较逻辑夹具摘要和业务结果, 保存各轮独立证据.
- [x] 1.5 移除 `ledgerctl experiment baseline` 和原型中的实验包引用, 调整原型离线测试入口的包范围. 用 `go list -deps -test ./cmd/... ./internal/... ./chaincode/...` 核对原型和项目测试的传递依赖, 运行 `mise run ledger:build` 和 `mise run test:unit`. 更新现行基线运行说明并用文档中的命令验证入口.

## 2. 保留独立的项目集成回归

- [x] 2.1 清点 `ledgerctl verify` 和实机定点回归的现有场景, 给每项记录可定位的去向. 核对通道治理, 原交易恢复, 固定高度与探针, 协议出示, 双根采购, 幂等和核账均有项目行为断言.
- [x] 2.2 将项目回归接到独立的测试入口, 保留按能力筛选, 超时, 诊断材料和失败退出. 在干净实例运行完整回归并按 2.1 对照覆盖, 再执行一项定点回归核对选择器和输出.
- [x] 2.3 将撤销窗口等实验专用采样, 统计和导出移出项目回归. 对原预跑中仍适用的行为断言, 核对项目测试可独立验证采用撤销块后拒绝及探针过期拒绝. 保留现有预跑证据, 在实验侧记录旧采样入口的迁移去向.
- [x] 2.4 从原型命令移除旧 `ledgerctl verify` 分支, 将 `mise run ledger:verify` 接到项目测试. 更新当前运行说明并按说明跑通, 核对原型构建依赖与基线运行入口.

## 3. 按能力重命名实现和测试

- [x] 3.1 按能力重命名活跃实现和测试中的 D0/M2/M3 文件名, 类型, 函数和回归选择器. 同步更新现行运行示例, 搜索剩余阶段标识并说明持久化及协议兼容出处.
- [x] 3.2 核对旧链码响应和存量夹具的兼容路径. 验证旧 `D0:` 错误仍可映射原原因码, 含 `m2TaskSpec` 的存量夹具仍可用于钱包装配, 并检查历史证据和归档未被改写.
- [x] 3.3 用最终构建复核原型传递依赖, 离线测试, 项目集成回归和独立基线的正常入口. 汇总覆盖与运行 ID, 并核对 [正式实验工作流](../standardize-experiment-workflow/proposal.md) 中的基线运行说明与迁移后的入口一致.
