# M4 三域 Web 工作台

## Why

现有原型具备 Fabric 登记, 供应商验权, 钱包与 MCP 工具及模型运行器, 人员操作仍依赖 CLI 和联调程序. M4 需要让 A/B/C 域人员从浏览器登录, 办理各自有权处理的业务, 并用真实链上操作和智能体执行记录演示采购过程.

## What Changes

- 提供 A/B/C 共用的 Web 前端和 Go 后端, 分别构建镜像, 通过同一份 Compose 模板和域配置部署, 通过版本化 HTTP API 与 OpenAPI 契约协作.
- 为三域管理员提供登录和本域管理入口. 为 A 域采购员 U 提供任务对话, 草稿确认, 正式创建任务, 签发委托, 派单和执行进度查询.
- 整理 Web 后端与 MCP 复用的强类型业务操作. 工作台启动的 Agent 按域, 主体和任务绑定工具权限, 由 A1 执行转委托, 由 B1 使用自己的钱包向 C 询价及模拟下单.
- 交付身份与信任, 凭证披露, 委托树, 采购任务和决策时间线视图. 浏览器演示覆盖 RP/BM 根来源, 800 元成单, 1200 元超额拒绝, 以及授权失效和恢复或核账.

## Capabilities

### New Capabilities

- `domain-web-workbench` - 三域可复用的工作台部署, 浏览器身份与角色权限, 采购交互和可核对的业务证据.

### Modified Capabilities

- `agent-tool-runtime` - 增加业务操作的共同调用边界, 以及工作台派发的 Agent 会话和跨域执行身份约束.

## Impact

- 平台新增 Web 后端, 浏览器会话及任务运行记录. 复用 `registrysvc`, `gateway`, `agent` 与 `runtime` 现有业务逻辑, 以真实状态装配工作台调用路径.
- 前端独立构建, 提供浏览器工作台. 基础设施新增前后端镜像和按域部署的 Compose 模板, 接入已有 Fabric 通道和 PostgreSQL.
- 更新项目操作说明, 业务契约和 M4 验收入口. 范围为现有 A/B/C 三域及固定采购场景, 沿用已接受的通道治理, 任务创建资格, 采购授权和模拟订单契约.
