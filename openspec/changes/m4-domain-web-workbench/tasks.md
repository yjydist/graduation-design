# M4 三域 Web 工作台实施任务

## 1. 共享业务操作

- [x] 1.1 整理浏览器与 MCP 共用的强类型业务操作, 复用管理, 钱包, 交付和网关逻辑并保留原 CLI 与 MCP 调用契约. 用配对输入回归相同主体的判据, 错误码和幂等副作用, 并更新平台模块边界说明.
- [x] 1.2 为工作台装配基于已确认交易, 固定高度登记和实际任务材料的签发与交付, 将现有夹具装配留给联调入口. 验证未确认交易, 未交付授权和过期材料无法推进流程, 重投可找回原回执.
- [x] 1.3 为工作台创建绑定部署, 域, 主体, 任务, 模式和授权的 MCP 会话. 验证工具清单按执行阶段裁剪, 改变签名主体, 任务或委托的参数被拒绝, 进程内与 stdio 回归继续通过.

## 2. 浏览器 API 和本域管理

- [x] 2.1 建立独立 Go Web 入口及 `/api/v1` OpenAPI 契约, 定义会话, 管理, 草稿, 运行和证据接口. 验证契约可解析且路由及错误信封与实现相符, 补充浏览器 API 与现有业务接口的分工说明.
- [x] 2.2 用平台迁移持久化本域账号映射和会话, 接通预置账号登录, 退出, CSRF 防护和权限发现. 覆盖 A/B/C 管理员及 U, 回归跨域会话, 伪造角色, 退出后重用和缺失 CSRF 校验的请求.
- [x] 2.3 接通本域管理员的 PA 资格操作和原交易状态查询, 为演示域准备合规本域服务. 验证三域分别按本域角色产生有效交易, 重试返回原 `operationId`, 越权请求无交易或信息泄露.

## 3. 采购对话及 A/B/C 执行

- [x] 3.1 接通 U 和 A1 的文本交互及带版本的任务草稿确认. 回归草稿未确认, 旧版本确认和并发重复确认, 验证仅有效确认产生持久化的任务 ID 与运行 ID.
- [x] 3.2 实现 U 创建任务, C 或 PA 分别签发 RP/BM 的 G0, U 签发和交付 G1, 以及 U 暂停和恢复 G1. 测试不同模式签发者, 失败阶段回显, 待确认状态的重启恢复和重复提交复用原交易.
- [x] 3.3 以本域 A1 模型运行器转委托 G2, 在 B 域核验材料交付和派发来源后以 B1 MCP 执行实际询价与下单, C 继续通过正式网关定案. 核对各域绑定, 重复派发的业务键, 暂停后拒绝及未知结果保留与核账, 文档记录运行状态和重试边界.
- [x] 3.4 持久化任务进度及脱敏工具轨迹并提供关联查询, 让页面断开或服务重启后可以继续查询. 验证轨迹区分模型停止, 网关实际拒绝, 未知与已定案, 可定位原操作, 工具调用及网关结果.

## 4. 浏览器交互与证据视图

- [x] 4.3 接通身份与信任, 凭证披露, 委托树, 采购任务和决策时间线五个视图. 核对真实认证与密钥版本, 实际披露, 委托收缩和失效祖先, 报价与副作用, 策略和环境版本, 块高/哈希及原探针期限. 验证任务摘要与完整决策的授权边界, 并更新演示交付及证据查询契约.
