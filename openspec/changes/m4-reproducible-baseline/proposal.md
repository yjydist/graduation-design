# 提案

## 背景与动机

现有验收已验证 RP/BM 采购闭环, 并分别覆盖 Fabric 视图和静态验签缓存. M4 需要将这些能力接入可重建的对照实验, 先验证三组使用同一准入语义, 再用正式实验衡量状态来源, 验签复用和后台成本的影响.

## 变更内容

- 提供 C0 中心化一致快照, B0 Fabric 逐次装配和 B1 Fabric 加静态验签缓存三种实验配置. C0/B0 对照登记状态提供方式, B0/B1 对照跨请求静态验签复用.
- 固定三域夹具生成规则, 目录价格, OPA 策略输入, 配对种子和原始记录格式. 每轮可从运行清单定位到真实请求, 状态版本, 决定与业务主库结果.
- 复用确定性钱包工具, 对每组作 RP/BM 两种授权模式下的真实询价和下单. 800 元应创建唯一订单, 1200 元应明确以超额拒绝且不产生订单或订单业务键.
- 首轮范围为三组接线, 业务一致性和干净环境复跑. 消融, E1/E3 真实 LLM 正式采样, E2/E4-E8 正式测量, 演示视图和论文属于 M4 后续工作.

## 能力

### 新增能力

- `reproducible-procurement-experiments` 提供三种可配对执行的采购实验配置, 夹具复现, 结构化原始结果与跨配置准入核对.

## 影响

- 实验入口复用 `ledgerctl`, Fabric 部署与种子数据, 钱包工具, 协议验证器和现有资源网关. 网关需要支持读取来源对应的锁后检查点与审计元数据, C0 使用独立的中心化登记预置和读取路径.
- 实验目录保存脱敏的运行清单, 请求, 主库核对和汇总. 判据沿用 [实验计划](../../../docs/experiments/实验计划.md#1-实验地图与同语义对照)及 [采购闭环用例](../../../docs/experiments/验证用例.md#1-采购闭环).
