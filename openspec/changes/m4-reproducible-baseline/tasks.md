# 实施任务

要求见 [增量规范](specs/reproducible-procurement-experiments/spec.md), 具体夹具, 流程及字段见 [设计](design.md).

## 1. 固定实验输入

- [x] 1.1 固定三域逻辑夹具, OPA 策略配置, 目录价, 期限规则及种子集合. 以生成测试核对同一种子重复生成的逻辑摘要及 RP/BM 计划一致, 种子不参与密钥, 盐及挑战生成.
- [x] 1.2 复用真实签发, 登记和钱包交付, 生成同轮共享的 RP/BM 材料并准备中心化登记输入. 核对预置输入使用签发用的 T 根及公开材料, 且两种根的逐跳金额和剩余深度均与设计一致.
- [x] 1.3 单独标注预置输入摘要. 在采购开始前从 C0 主库和已应用 Fabric 视图独立读取并比较共同锚点, 分别记录检查点和对象版本. 验证版本差异可接受, 锚点变化或缺失时保留失败证据, 并从干净环境复跑.

## 2. 接通三组状态来源

- [x] 2.1 将快照来源对应的检查点锁定与复核接入现有网关业务事务. 用已有 Fabric 回归核对块推进触发整次重验, 探针原期限和锁后风险复核.
- [x] 2.2 实现 C0 主库预置及一致快照读取, 使登记更新与 `revision` 递增原子提交. 测试缺失依赖停止装配, 读事务不混版本, 锁等待期间版本变化后整次重验, 并核对 C0 可独立于 Fabric 服务作出决定.
- [x] 2.3 将状态来源, 中心化版本和读取时点写入决策, 支持 C0 的 Fabric 字段为空. 以已存在的 Fabric 决策行核对迁移可重复执行且读取, 历史复查结果一致, 并验证 C0 决策可按实际版本关联.
- [x] 2.4 接入三组配置的静态验签缓存开关和计数, 核对 C0/B0 不复用签名计算, B1 重复材料出现命中且采用新状态后仍拒绝失效材料.

## 3. 实验入口与原始记录

- [x] 3.1 实现 `ledgerctl experiment baseline` 对隔离实例的确定性驱动, 使用真实钱包执行目录价设置, 风险观测, 询价和下单. 核对 12 个订单用例及对应询价的计划顺序, 每动作新挑战, 独立业务键, 并确保超价请求按 Q1200 实际金额提交.
- [x] 3.2 导出 `manifest.json`, `requests.csv`, `order_checks.csv`, `summary.json`, 实现 HTTP 和主库结果的联合判定及跨组比较. 用导出测试核对列序, 单位, 空值, 请求对账, 挑战与决定关联, 以及预期拒绝记为通过且不产生订单或订单业务键.
- [x] 3.3 使受入口管理的准备失败, 请求超时或主库核对出错保留独立证据并非零退出. 执行故障样例, 核对未执行项与缺测原因可追溯, 并扫描产物以确认无私钥, 账号盐, 完整披露或访问令牌.
- [x] 3.4 在 Fabric 运行说明中记录环境准备, 隔离实例运行命令及证据复跑步骤. 照文档执行一轮并找到设计规定的四个原始文件.

## 4. 首轮集成验收

- [x] 4.1 使用 `1109` 从两个独立干净环境重建并运行, 每轮核对 12 次询价允许, 6 笔 800 元唯一订单及 6 次 1200 元 `403 AMOUNT_LIMIT_EXCEEDED` 拒绝. 核对各组状态来源, 挑战和决定, 拒绝侧无订单或订单键, 并确认 B1 观测到静态验签命中.
- [x] 4.2 比对两轮的逻辑夹具摘要, 配对用例矩阵, 业务判定和主库副作用, 将实际部署, 原始文件及失败样本收录到证据索引. 通过索引抽查任一成功与拒绝用例均可回溯到对应尝试的请求, 状态版本, 决定和主库核对.
