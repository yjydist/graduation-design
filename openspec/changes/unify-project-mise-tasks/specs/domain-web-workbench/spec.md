# 本地三域演示部署

## ADDED Requirements

### Requirement: 一条命令交付可登录的三域工作台

在支持的演示主机上, 系统 SHALL 提供 `mise run demo:up`. 操作者预先提供 A/B 模型连接配置和密钥后, 此命令 SHALL 完成隔离 Fabric 网络, 链码, 协议材料, 前后端镜像及三域服务的准备. 成功时 SHALL 输出各域 HTTPS 地址, 可用账号, 口令文件位置和浏览器根证书的信任指引. 交互采购由采购员在工作台确认.

#### Scenario: 从空环境启动并核对三域入口

- **WHEN** 操作者在满足依赖且没有演示实例的主机运行 `mise run demo:up`
- **THEN** 任务经每域浏览器入口验证该域 CA, 请求 `/api/v1/health/ready`, 核对 `ready=true` 及与目标相符的 `domainId`, 三域均通过后返回成功
- **AND** 操作者按输出指引信任本地证书后, 可用 A 域 `u`, B 域 `admin` 和 C 域 `auditor` 登录对应工作台. 凭据以文件位置提示, 终端输出不含密钥或口令值

#### Scenario: 启动前即可定位配置缺失或端口冲突

- **WHEN** 首次启动时缺少所需的 A/B 模型配置, 或目标端口已由其他实例占用
- **THEN** 任务在创建演示服务前指出缺失项或冲突端口并以非零状态退出

#### Scenario: 有一个域未就绪

- **WHEN** 部署过程中某域超时, HTTPS 证书校验失败或返回另一域的标识
- **THEN** 命令以非零状态指出失败域和阶段, 可用 `demo:status` 和 `demo:logs` 继续定位

### Requirement: 重复启动与中断恢复沿用实例身份

再次执行 `demo:up` 时, 系统 SHALL 核对当前演示归属, 部署标识, 已准备材料及有效期. 对完整有效的部署 SHALL 复用原账本, 各域数据库, 登录口令和证书. 部分完成的部署 SHALL 从可核对的步骤续跑, 或报告需要处理的阶段及显式重建入口.

#### Scenario: 在就绪和中断两种状态下重跑

- **WHEN** 操作者对就绪实例连续运行 `demo:up`, 或在某域启动中断后再次运行
- **THEN** 已完成的有效阶段可以复用, 同一部署只产生一套有效域材料, 已有订单与运行 ID 仍可查询
- **AND** 同一实例上的并发启动和清理有确定的先后结果, 或其中一个收到实例忙的反馈

#### Scenario: 旧实例的在线采购材料已过期

- **WHEN** 恢复实例时演示夹具已经超过记录的有效期
- **THEN** `demo:up` 返回非零状态, 报告到期时间及清理后重新部署的命令, 并保留旧账本和业务记录供复核

### Requirement: 默认停机保留现场并支持显式彻底清理

`mise run demo:down` SHALL 关闭工作台及其 Fabric 网络, 释放端口并保留数据. `mise run demo:clean` SHALL 一次关闭并删除该演示所属的容器, 网络, 命名卷及生成目录, 适用于运行中, 已停机, 部分部署和已清理的实例. 两个操作 SHALL 可以在模型服务或模型输入不可用时执行.

#### Scenario: 停机后继续同一场演示

- **WHEN** 操作者在材料有效期内先运行 `demo:down`, 再运行 `demo:up`
- **THEN** 停机时端口释放, 恢复后部署标识, 浏览器 CA 和账号口令与停机前一致, 原运行及订单可按原 ID 查询

#### Scenario: 在其他实例并存时一键清理并重建

- **WHEN** 独立实验实例与演示实例并存, 操作者直接运行 `demo:clean`, 再次运行 `demo:clean`, 然后执行 `demo:up`
- **THEN** 两次清理均成功, 演示资源和生成的私有文件已清除, 下一次部署得到新的部署标识
- **AND** 其他实例的资源, 实验原始记录, 外部模型输入和共享镜像缓存均保持可用

#### Scenario: 对部分部署清理时出现故障

- **WHEN** 演示只创建了部分服务, 删除其中一个归属明确的资源时 Docker 返回失败
- **THEN** 清理以非零状态返回可定位的剩余资源, 操作者修复故障后可重跑直至清空
- **AND** 遇到归属不明的目录或 Compose 项目时, 系统报告原因并保留该资源

### Requirement: 可以从新终端查看演示状态和日志

系统 SHALL 提供 `mise run demo:status` 和 `mise run demo:logs`, 根据本地演示实例定位 Fabric 及三域工作台. 查询 SHALL 可直接从新终端运行, 区分未创建, 部分启动, 已停机及就绪状态, 提供按域或服务定位的诊断, 并保护凭据内容.

#### Scenario: 在未初始化和部分启动时查询

- **WHEN** 操作者在没有演示实例时查询, 或在 B 域未就绪时从新终端查询运行状态和 B 域日志
- **THEN** 前者报告未创建, 后者能指出 B 域状态并返回对应的可用诊断. 查询本身不创建实例, 容器, 卷或新证书
