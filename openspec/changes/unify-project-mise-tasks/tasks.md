# 实施任务

## 1. 根任务和项目工具

- [ ] 1.1 在根 `mise.toml` 保留现有 13 个任务, 补齐设计表中的链码构建, `ledgerctl` 七个子命令, Fabric 网络脚本动作以及工作台构建, 准备和单域服务启动. 接入规范维护入口 `spec`. 对照 `mise tasks`, 各工具帮助及 `mise run spec -- list --specs` 核对覆盖率, 从根检查带空格的实参和失败退出状态.
- [ ] 1.2 接入 `test:arch`, `test:vet`, `test:race` 和 `test:fabric:compile`. 运行两套架构守卫, 检查模块依赖图及协议登记包的标准库依赖, 用单个 Go 包验证竞态参数和 CGO 作用域, 在未启网时编译 fabriclive 测试.
- [ ] 1.3 验证可脚本化调用的输入输出. 在隔离测试材料上通过根 `ledger:mcp` 完成一次标准输入输出握手, 检查标准输出仅含 MCP 消息. 更新根和相关 Go 模块手册的命令示例, 从仓库根执行其中的构建和只读帮助命令.

## 2. 前端开发入口

- [ ] 2.1 在根工具链加入 Node 22, 接入 `web:install` 和全部七个 npm 脚本, 正确处理工作目录与参数分隔符. 对照 `web/package.json` 核对没有遗漏, 在干净检出中执行安装, 再从根给 `web:dev` 和 `web:preview` 传入自定义端口并确认地址可访问.
- [ ] 2.2 接入 `web:check`, 让预览和浏览器回归自动构建当前前端. 从没有 `dist/` 的临时检出运行 `mise run web:test:browser`, 在没有浏览器依赖的环境独立运行 `web:check`. 更新根 README 和前端指南, 逐条核对安装及检查示例.

## 3. 实验命令和证据迁移

- [ ] 3.1 迁移四个 `experiment:*` 任务, 补充 `experiment:build`, 将 E1 的 `run.sh` 指向根任务, 移除子目录重复配置. 在根执行三个子命令的 `--help` 和 `experiment:test`. 用不支持的编号验证非零退出, 用相对路径和含空格的绝对路径验证参数原样到达 CLI.
- [ ] 3.2 更新 `experiments/baseline/baseline.go` 的文件锁定清单及 `experiments/cmd/exp/run.go` 中 E1/E6 的快照输入. 扩展现有基线与计划模式测试, 从实际清单及解包后的快照重算根配置和适用脚本的摘要, 验证移除子配置后仍可生成完整记录.
- [ ] 3.3 更新根及实验模块指南, 基线和 E1/E6 手册中的入口与路径示例. 从仓库根用 E1/E6 的小型测试记录执行 `experiment:analyze`, 核对派生文件位于指定目录, 输入摘要前后一致. 用文档中的相对实例路径核对 `baseline` 和 `run` 指向预期隔离实例.

## 4. 三域演示部署和回收

- [ ] 4.1 在 `infra/workbench/` 建立共用运维入口, 实现 `workbench:images`, `compose`, `certs`, `ready` 和 `probe` 对应任务. 用指定域的 Compose 配置核对项目名, 网络, UID/GID, 镜像标识及独立挂载, 检查探针沿用调用者给出的运行 ID 和键.
- [ ] 4.2 实现演示专用目录的归属记录, 进程锁, A/B 模型输入及端口预检. 用临时工作区测试缺少模型文件, 其他实例占用端口, 非本实例目录和并发调用. 核对失败原因及退出状态, 并验证预检失败时尚未创建服务.
- [ ] 4.3 实现 `demo:up` 的新建和恢复路径. 复用 Fabric 启停, 链码部署, 写入夹具与账本检查, 以临时目录准备三域材料, 按已绑定镜像启动各域. 用离线编排测试覆盖二次启动, 准备阶段中断及夹具过期, 核对有效身份和材料可以复用, 过期实例返回重建提示.
- [ ] 4.4 经每域自己的 CA 和 HTTPS 入口检查 `ready` 与 `domainId`, 输出网址, 账号, 口令文件和证书指引. 接入 `demo:status` 和 `demo:logs`. 模拟超时, 域标识错误及证书错误, 验证能从新终端定位失败域, 空实例查询无副作用, 输出不含口令或密钥值.
- [ ] 4.5 实现保留现场的 `demo:down` 和可直接运行的 `demo:clean`. 测试工作台先于共享 Fabric 网络关闭, 清理中断后可重试, 在运行中, 停机后和重复清理时结果正确. 用独立 Compose 项目, 外部模型文件及目录符号链接核对删除范围.
- [ ] 4.6 将运维离线回归接入 `test:demo`. 更新根 README, 基础设施指南和工作台手册, 写清一次性模型配置, 浏览器 CA 信任, 两种关闭方式及到期处理. 从新终端按手册运行 `demo:status` 和日志查询, 核对无需手工定义 shell 函数或重新导出部署变量.

## 5. 聚合入口与端到端验收

- [ ] 5.1 连接根 `build` 和 `test` 的任务依赖, 在根 README 给出演示, 开发检查和实验三条最短操作路径. 安装依赖后在未启动 Docker 和未提供模型密钥的环境运行两项聚合任务, 核对四个可执行文件, `web/dist/` 和四组离线测试结果.
- [ ] 5.2 在支持的独立 arm64 主机从空演示目录运行 `mise run demo:up`. 从三个 HTTPS 地址分别登录, 由采购员确认一笔 P1 采购并记下运行和订单 ID. 在有效期内再次 `up`, 再 `down` 后 `up`, 核对同一部署, 登录口令, CA 及原业务记录.
- [ ] 5.3 在同机保留另一个测试实例和独立实验记录, 从运行态直接执行 `demo:clean`, 再次执行并重新部署. 核对旧演示容器, 网络, 卷和生成目录已清除, 端口已释放, 新部署标识不同, 对照实例仍可用且证据摘要一致. 对仅启动部分域的演示重复定向清理验收.
